# Affirm — 显化导师 AI Agent

**更新日期**：2026-03-19
**项目状态**：已部署，持续迭代

---

## 项目定位

Affirm 是一个基于 Telegram Bot 的个人 AI 显化导师助手。用户通过 Telegram 进行长期对话，系统具备向量语义记忆、知识库注入、每日对话归档（Notion）以及 Web 管理后台等能力。

---

## 核心特性

| 特性 | 状态 | 说明 |
|------|------|------|
| Telegram Bot 对话 | ✅ 生产可用 | Polling / Webhook 双模式，用户级串行队列 |
| 多 AI Provider | ✅ 生产可用 | DeepSeek / Claude / OpenAI 可切换 |
| 消息持久化 | ✅ 生产可用 | PostgreSQL，含 pgvector 向量列 |
| 向量 Embedding | ✅ 生产可用 | 独立 Embedding Provider（`EMBEDDING_API_KEY`），与主 AI Provider 解耦 |
| 语义记忆检索 | ✅ 生产可用 | RAG 已接入对话链路，历史消息语义检索启用 |
| 知识库注入 | ✅ 生产可用 | Admin 界面录入，RAG 自动检索并注入 Prompt |
| Notion 归档 | ✅ 可用 | `/archive_now` 命令手动触发 |
| Web 管理后台 | ✅ 可用 | Express + EJS，HTTP Basic Auth + CSRF Origin 校验 |

## RAG 当前阶段

Affirm 当前属于“基础可用型 Conversational RAG”，不是纯文档问答系统。

当前已经具备的能力：

- 知识库检索：从 `knowledge_chunks` 中检索相关知识片段
- 语义记忆检索：从 `messages` 中检索用户历史相关对话
- 时序上下文：保留最近 N 条消息作为短期记忆
- v1 chunking：后台长文本导入时自动按段落切分、短段合并、长段切片
- Prompt 注入：将知识片段和历史记忆一起注入 LLM 上下文
- 失败降级：`EMBEDDING_API_KEY` 缺失或 embedding 失败时，自动退化为纯时序上下文

当前尚未实现的增强项：

- reranker
- query rewrite
- hybrid search
- citation / 回答依据展示

说明：

- 基础 chunking 已在当前版本落地
- 更复杂的 chunking 流水线（标题感知、语义分块、元数据保留）仍属于后续增强
- 其余增强项都不是当前版本的前置条件；它们属于“检索质量优化”和“可观测性增强”，应按问题出现的顺序逐步补齐

## 技术栈

| 层次 | 技术 |
|------|------|
| 运行时 | Node.js 18+（CommonJS）|
| Bot 框架 | node-telegram-bot-api（Polling / Webhook）|
| AI 客户端 | openai npm 包（统一兼容接口）|
| 数据库 | PostgreSQL 15+ + pgvector 0.8.x |
| 管理后台 | Express 4 + EJS + Helmet |
| 配置管理 | dotenv + 自研 ConfigManager |
| 错误处理 | 自研 ErrorHandler + 自定义错误类 |
| 并发控制 | BullMQ（Redis）+ 内存队列降级 |
| 容器化 | Docker + docker-compose |
| 进程管理 | PM2 |

## AI Provider 配置

通过 `AI_PROVIDER` 环境变量选择提供商：

```bash
AI_PROVIDER=deepseek    # DeepSeek（默认）
AI_PROVIDER=claude      # Claude via AiGoCode 代理
AI_PROVIDER=openai      # OpenAI 官方
```

所有 Provider 统一使用 OpenAI 兼容接口，无需更换代码。

---

## 环境变量（核心）

```bash
# 数据库
DB_URL=postgresql://user:password@localhost:5432/affirm

# Telegram
TELEGRAM_BOT_TOKEN=your_bot_token

# AI Provider
AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=your_deepseek_key

# 可选：Claude
CLAUDE_API_KEY=your_claude_key
CLAUDE_BASE_URL=https://api.aigocode.com/v1

# 可选：Notion 归档
NOTION_TOKEN=your_notion_token
NOTION_DATABASE_ID=your_database_id

# Embedding（RAG 语义检索，独立于主 AI Provider）
EMBEDDING_API_KEY=your_openai_api_key
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_DIMENSIONS=768

# 安全
JWT_SECRET=your_jwt_secret
CORS_ORIGINS=http://localhost:3000
```

完整环境变量模板见 `.env.example`。

说明：

- `ADMIN_PASSWORD` 为当前管理后台实际认证必填项（HTTP Basic Auth）。
- `JWT_SECRET` 当前代码中仅保留配置项，后台认证未使用 JWT（⚠️ 待实现，如后续改造为会话/JWT 模式）。

## 快速开始

```bash
# 1. 复制环境变量模板
cp .env.example .env

# 2. 填写必要配置（DB_URL、TELEGRAM_BOT_TOKEN、AI Key）

# 3. 启动服务（Docker）
docker-compose up -d

# 4. 或本地启动
npm install
npm start
```

### RAG 增强项建议优先级

| 优先级 | 模块 | 是否建议现在就做 | 说明 |
|--------|------|------------------|------|
| 已完成 | 基础 chunking（v1） | 已实现 | 后台导入已支持自动切分长文本 |
| 高 | citation / 检索依据展示 | 是 | 便于排查回答依据，帮助后续维护和调优 |
| 中 | hybrid search | 按需 | 适合包含专有名词、日期、固定关键词的知识库 |
| 中 | query rewrite | 按需 | 适合用户问题省略上下文、指代较多的场景 |
| 中低 | reranker | 按需 | 当语料规模增长、topK 排序质量下降时再引入 |

### 一个简单判断标准

- 检索不到：先检查现有 chunking 是否足够，再考虑 query rewrite / hybrid search
- 检索到了但前几条不准：考虑 reranker
- 回答像“编的”，不知道依据来自哪：先补 citation
