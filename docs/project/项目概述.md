# 项目概述

**项目名**：Affirm  
**定位**：Telegram 上的 AI 显化导师  
**更新日期**：2026-04-14
**当前状态**：v2 最小闭环已可运行；产品目标中的长期记忆体验尚未全部落地

## 1. 这个项目在做什么

Affirm 不是单轮问答机器人，而是一个长期陪伴型的显化导师系统。它需要同时解决五件事：

1. 记住最近几轮对话
2. 维护用户稳定长期记忆
3. 从大量历史经历中召回相关片段
4. 在需要时引入外部知识
5. 让后台和运维层能看见这些状态

因此它的核心不是“接一个模型”，而是把对话、稳定记忆、历史召回、知识检索拆成有边界的系统。

## 2. 当前技术栈

- 服务端：Node.js
- 数据库：PostgreSQL
- 队列：BullMQ + Redis，支持内存降级
- 外部知识检索：Haystack
- 模型接入：OpenAI 兼容 SDK
- 管理后台：Express + EJS
- 归档：Notion

## 3. 项目想达到的效果

理想中的显化导师，不只是“能回答问题”，而是要给用户这类体验：

1. 机器人知道用户是谁，最近在追什么目标
2. 机器人知道用户常见的阻碍、偏好、语言风格和自我叙事
3. 机器人知道用户上次答应了什么、最近有没有进展、曾经有哪些关键突破
4. 当用户再次提到类似主题时，机器人能主动召回相关历史，而不是完全重新认识这个人
5. 外部知识是辅助层，不能替代用户记忆本身

## 4. 当前已经实现的闭环

当前已经实现的是“v2 最小闭环”，不是完整的长期记忆目标架构。

### 当前已经落地的层

| 层级 | 当前方案 | 职责 |
|------|----------|------|
| 原始日志 + 短期上下文 | `messages` | 保存原始对话与最近 N 条消息 |
| 稳定长期记忆 | `profiles` | 保存结构化长期记忆摘要 |
| 外部知识 | `Haystack` | 负责知识导入、切块、检索 |
| 回答生成 | Node 主链路 | 统一拼装 prompt 并调用模型 |
| 工程治理 | `MemoryService` / `sync_jobs` / `trace` | 负责记忆更新、状态追踪和可观测性 |

当前对话时实际注入的是：

`system -> profile memory -> recent messages -> knowledge -> user message`

这意味着当前系统已经能做到：

1. 读最近上下文
2. 读稳定记忆
3. 读外部知识
4. 回复后更新稳定记忆

但当前系统还做不到：

1. 从大量历史对话中召回相关经历
2. 把稳定记忆和历史事件记忆拆成两个不同层
3. 对历史记忆做 hybrid retrieval

## 5. 当前实现和目标效果的差距

当前主要差距有四个：

### 5.1 只有稳定记忆层，没有历史事件记忆层

当前长期记忆主要压缩在 `profiles.preferences` 里。
这适合保存稳定事实，但不适合保存大量、可召回的历史经历。

### 5.2 只有最近消息上下文，没有长期历史召回

当前主链路只读取最近 `messages`。
一旦重要信息没有被提炼进 `profiles`，几轮之后就会丢失。

### 5.3 外部知识和用户历史是分开的，但用户历史检索层还没建出来

这是好事也是短板：

1. 好事：没有把用户记忆和知识库混在一起
2. 短板：当前缺少专门的“用户历史记忆检索层”

### 5.4 `profiles` 的结构还偏粗

现在更像是通用的长期记忆摘要，不够贴合显化导师场景。
未来应更细分为：

- 身份愿景
- 当前目标
- 长期阻碍
- 支持性信念
- 限制性信念
- 偏好的提醒方式
- 当前承诺
- 已取得的胜利

## 6. 目标中的长期记忆架构

对于这个项目，更合理的长期记忆架构应该是四层：

### 6.1 `messages`

- 原始聊天日志
- 保留完整细节
- 作为审计、回放、摘要来源

### 6.2 `profiles`

- 稳定长期记忆
- 适合存“这个人是谁、长期在追什么、偏好什么”
- 作用类似精选过的 `MEMORY.md`

### 6.3 `memory_events`（计划新增）

- 可检索的历史事件记忆
- 适合存“用户上次发生了什么、说过什么、承诺过什么、最近突破了什么”
- 应支持 hybrid retrieval，而不是只靠时间顺序

### 6.4 `Haystack`

- 只负责外部知识
- 不负责用户长期记忆
- 不负责用户历史事件召回

## 7. 当前最小闭环怎么定义

当前“跑通”标准是：

1. Telegram 消息能进入主链路
2. `messages` 能保存 user / assistant 对话
3. `profiles` 能读取和更新
4. AI 能正常回复
5. 回复后会异步触发 `MemoryService`
6. `sync_jobs` 和后台可观察这条链是否成功

这已经足够作为 v2 最小可运行版本，但还不能说“长期记忆体验已经完整实现”。

## 8. 当前推荐的演进方向

当前推荐的下一阶段不是恢复旧的 `messages` 语义记忆，而是：

1. 新增 `memory_events` 表
2. 在回复后同时生成：
   - `profile patch`
   - `episodic memory candidates`
3. 对 `memory_events` 做 hybrid retrieval
4. 在 prompt 中增加“历史相关记忆片段”
5. 让上下文从三层变成四层：

`profile memory -> recalled memory events -> recent messages -> knowledge`
