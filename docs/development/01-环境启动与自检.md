# 01 环境启动与自检

## 1. 前置条件

- Node.js 18+
- PostgreSQL
- Telegram Bot Token
- 一个可用的 AI Provider Key

可选：

- Redis
- Notion API Key
- OpenAI / Embedding Key

## 2. 标准启动步骤

```bash
cp .env.example .env
npm install
npm run db:migrate
npm run verify
npm start
```

后台单独启动：

```bash
npm run admin
```

## 3. 推荐检查顺序

### 第一步：环境变量

至少保证这些值存在：

```bash
DB_URL
TELEGRAM_BOT_TOKEN
AI_PROVIDER
ADMIN_PASSWORD
```

### 第二步：数据库

```bash
npm run db:migrate
node scripts/utils/test-database.js
```

### 第三步：应用状态

```bash
npm run verify
./scripts/utils/quick-verify.sh
node tools/check-status.js
```

## 4. 关于 RAG key 的判断

当前规则：

1. 有 `EMBEDDING_API_KEY`，直接用
2. 没有，但有 `OPENAI_API_KEY`，knowledge RAG 复用它
3. 两者都没有，knowledge RAG 进入 deterministic fallback

所以：

- 项目可以在没有独立 embedding key 的情况下启动
- 但如果你要验证检索质量，最好有远程 embedding key

## 5. 常见问题

### `npm run verify` 失败

优先检查：

- `.env` 是否存在
- `DB_URL` 是否可连
- PostgreSQL 是否启动

### Bot 能启动但回答质量很差

优先检查：

- `knowledge_rag` 是否处于 deterministic fallback
- 是否真的导入了知识片段

### 集成测试失败

先确认：

- 本地数据库可用
- 测试库 schema 已迁移

## 6. 这个流程什么时候算完成

- `npm run db:migrate` 成功
- `npm run verify` 成功
- `npm start` 能正常启动
- `npm run admin` 能打开后台
