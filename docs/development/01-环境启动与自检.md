# 01 环境启动与自检

## 1. 前置条件

- Node.js 18+
- PostgreSQL
- Telegram Bot Token
- 至少一个可用的大模型 API Key

增强模式额外要求：

- 一个可访问的 Haystack 服务

可选：

- Redis
- Notion API Key

## 2. 标准启动步骤

```bash
cp .env.example .env
npm install
npm run db:migrate
npm run verify
npm start
```

如果要启用知识增强，再补：

```bash
# 按你的部署方式启动 Haystack
npm run knowledge:sync
```

后台单独启动：

```bash
npm run admin
```

## 3. 当前配置入口

主应用配置链路固定为：

```text
.env / process env
  -> src/config.js
  -> application modules
```

规则：

- 应用的唯一配置输入源是 `.env`
- 代码里统一从 `src/config.js` 读取
- Haystack 和 Memory v2 的配置也走同一入口

## 4. 当前重点环境变量

### 主应用必填

```bash
DB_URL
TELEGRAM_BOT_TOKEN
ADMIN_PASSWORD
```

### 大模型

```bash
AI_PROVIDER=claude
CLAUDE_API_KEY=...
# 或 OPENAI_API_KEY=...
```

### Haystack

```bash
HAYSTACK_BASE_URL=http://localhost:8000
HAYSTACK_TIMEOUT_MS=10000
```

### Memory v2

```bash
MEMORY_V2_ENABLED=true
MEMORY_V2_RECORD_JOBS=true
MEMORY_V2_CONTEXT_MESSAGES=8
```

## 5. 推荐检查顺序

### 第一步：环境变量

至少确认这些值存在：

- `DB_URL`
- `TELEGRAM_BOT_TOKEN`
- `ADMIN_PASSWORD`
- `AI_PROVIDER` 对应的 key
- `HAYSTACK_BASE_URL`（仅知识增强模式必填）

### 第二步：数据库

```bash
npm run db:migrate
node scripts/utils/test-database.js
```

### 第三步：Haystack（可选增强）

至少确认：

- 服务可访问
- 健康接口正常
- 搜索接口能返回结果
- 历史知识能通过 `npm run knowledge:sync` 回填

### 第四步：应用状态

```bash
npm run verify
npm start
npm run admin
```

## 6. 当前 RAG 判断标准

当前架构下：

- 主应用不再直接依赖 `EMBEDDING_API_KEY`
- Embedding、检索、可选重排由 Haystack 管理
- 如果知识效果差，优先检查 Haystack 与同步状态，而不是旧的本地 embedding 链路

## 7. 常见问题

### Bot 能启动，但知识增强没效果

优先检查：

- Haystack 是否在线
- 知识是否真的导入
- 检索是否同时覆盖 `global + user-scoped`

### 回复有连续性，但记不住长期信息

优先检查：

- `profiles` 是否存在
- `profiles.preferences` 是否被更新
- `memory_update` 类型的 `sync_jobs` 是否成功

### 后台能保存知识，但聊天里查不到

优先检查：

- 是否真的同步到了 Haystack
- `rag_sync` 状态是否正常
- `scope / user_id` 是否正确

## 8. 什么算启动完成

- `npm run db:migrate` 成功
- Haystack 可访问
- `npm start` 能正常启动
- `npm run admin` 能打开后台
- Bot 发消息后能走完整条链路
- 未配置 Haystack 时，允许以 degraded 方式运行最小闭环
