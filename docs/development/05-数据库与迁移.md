# 05 数据库与迁移

## 1. 什么时候看这篇

当你要改这些内容时：

- 新增列
- 修改表结构
- 增加索引
- 增加触发器
- 修复数据同步逻辑

## 2. 先读哪些文件

按顺序读：

1. `scripts/database/schemas/init.sql`
2. `scripts/database/migrate.js`
3. `migrations/*.sql`
4. [数据库设计](../database/数据库设计.md)

## 3. 变更数据库的标准流程

1. 改 `init.sql`
2. 新增一个迁移文件
3. 运行：

```bash
npm run db:migrate
```

4. 如果影响数据读写，补对应测试
5. 更新数据库文档

## 4. 当前特别要注意的点

### `knowledge_chunks`

这个表现在不只是普通知识表，它还承担：

- 向量检索
- metadata 过滤
- 旧列兼容

因此你改这个表时，要同时考虑：

- `content`
- `embedding`
- `source`
- `user_id`
- `metadata`

### `messages`

表里虽然还有 `embedding`，但当前不是主开发方向。

## 5. 最小验证方式

```bash
npm run db:migrate
node scripts/utils/test-database.js
```

如果改的是 knowledge metadata，同步验证：

- Admin 新增知识
- Admin 批量导入
- `knowledge_chunks.metadata`
- `knowledge_chunks.source/user_id`

## 6. 哪些改动最容易出问题

1. 只改迁移，不改 `init.sql`
2. 只改表列，不改索引
3. 改了 metadata，忘了同步旧列
4. 改了 schema，没更新文档和测试
