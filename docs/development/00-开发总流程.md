# 开发总流程

**目标**：让你每次开发都知道“先看哪、改哪、怎么验”。

## 1. 固定起手顺序

每次开始一个新任务，都按这个顺序：

1. 先跑 [01-环境启动与自检](01-环境启动与自检.md)
2. 确认你要动的是哪个流程
3. 只读对应流程相关文件
4. 改代码
5. 跑最小验证
6. 更新对应文档

## 2. 先判断你属于哪类任务

| 任务类型 | 去哪里 |
|----------|--------|
| 项目跑不起来、环境不稳 | [01-环境启动与自检](01-环境启动与自检.md) |
| 用户消息处理、Prompt、Webhook、队列 | [02-Telegram 对话链路](02-Telegram-对话链路.md) |
| 知识新增、导入、检索、LangChain | [03-Knowledge RAG](03-Knowledge-RAG.md) |
| 后台页面、表单、列表、权限 | [04-Admin 后台](04-Admin-后台.md) |
| 表结构、迁移、索引、触发器 | [05-数据库与迁移](05-数据库与迁移.md) |
| 单测、集测、lint、提交流程 | [06-测试与交付](06-测试与交付.md) |

## 3. 当前推荐开发路径

如果你是重新接手这个仓库，按这个顺序最清晰：

1. 环境跑起来
2. 理解 Telegram 主链路
3. 理解 Knowledge RAG
4. 理解 Admin 后台
5. 最后再改数据库和测试

## 4. 当前最重要的边界

### 你应该优先投入的模块

- `src/services/telegram.js`
- `src/services/ai.js`
- `src/services/rag/knowledge-vector-store.js`
- `src/models/knowledge.js`
- `src/admin/routes/knowledge.js`

### 你现在不该优先投入的模块

- `messages` 语义记忆
- 旧 embedding service
- 历史 7 天开发脚本
- 历史审计/日报文档

## 5. 一个任务结束时至少要做的事

1. 跑对应最小验证
2. 确认没把任务做进错误流程
3. 更新相关文档
4. 再准备提交
