# 00 开发总流程

## 1. 固定起手顺序

每次开始一个新任务，都按这个顺序：

1. 先跑 [01-环境启动与自检](01-环境启动与自检.md)
2. 判断任务属于哪条链路
3. 只读对应链路相关文档和代码
4. 修改实现
5. 跑最小验证
6. 同步更新文档

## 2. 先判断任务属于哪类

| 任务类型 | 去哪里 |
|----------|--------|
| 环境起不来 / 配置异常 | [01-环境启动与自检](01-环境启动与自检.md) |
| Telegram 对话、Prompt、长期记忆 | [02-Telegram-对话链路](02-Telegram-对话链路.md) |
| Haystack、知识导入、检索 | [03-Knowledge-RAG](03-Knowledge-RAG.md) |
| Admin 后台、Dashboard、Sync Jobs | [04-Admin-后台](04-Admin-后台.md) |
| 表结构、迁移、索引、约束 | [05-数据库与迁移](05-数据库与迁移.md) |
| 测试、交付、验证 | [06-测试与交付](06-测试与交付.md) |

## 3. 当前推荐阅读顺序

如果你要改 v2 主线，按这个顺序最清晰：

1. [闭环 v2 架构](../architecture/closed-loop-v2-architecture.md)
2. [系统架构](../architecture/system-architecture.md)
3. [Telegram 对话链路](02-Telegram-对话链路.md)
4. [Knowledge RAG](03-Knowledge-RAG.md)
5. [Admin 后台](04-Admin-后台.md)
6. [数据库与迁移](05-数据库与迁移.md)

## 4. 当前优先投入的模块

- `src/services/telegram.js`
- `src/services/ai.js`
- `src/services/memory-service.js`
- `src/services/conversation-trace.js`
- `src/models/profile.js`
- `src/models/knowledge.js`
- `src/models/sync-job.js`
- `src/admin/routes/knowledge.js`
- `src/admin/routes/sync-jobs.js`
- `src/services/rag/provider.js`

## 5. 当前不应优先投入的模块

- `messages` 语义记忆恢复
- 旧的本地 `knowledge-vector-store`
- 过度复杂的 hybrid retrieval 细节
- 历史计划、旧日报、旧审计文档

## 6. 每个任务结束时至少要做的事

1. 跑对应最小验证
2. 确认没有把职责写到错误层
3. 更新文档
4. 再准备提交
