# 06 测试与交付

## 1. 开发完成后的最小动作

至少做这几件事：

```bash
npm run lint
npm run test:unit
```

如果改到了数据库、Admin 或路由，再跑：

```bash
npm run test:integration
```

## 2. 当前测试结构

```text
tests/
├── unit/
│   ├── models/
│   └── services/
└── integration/
    ├── admin-routes.test.js
    └── knowledge-metadata-sync.test.js
```

## 3. 什么时候补什么测试

| 改动类型 | 至少补什么 |
|----------|------------|
| 改 `Knowledge` | `tests/unit/models/knowledge.test.js` |
| 改 chunking | `tests/unit/services/chunking.test.js` |
| 改 Admin 路由 | `tests/integration/admin-routes.test.js` |
| 改 metadata 同步 | `tests/integration/knowledge-metadata-sync.test.js` |

## 4. 当前已知现实

- 集成测试依赖可用的 PostgreSQL
- 如果本地数据库没起来，`test:integration` 失败不代表业务代码一定坏了
- 交付前要区分“代码断言失败”和“环境不可用”

## 5. 交付前检查清单

1. 对应流程文档已更新
2. 没有把逻辑改到错误模块
3. 没有留下历史脚本或临时文档
4. 关键命令至少跑过一轮
5. 提交信息能准确描述本次改动
