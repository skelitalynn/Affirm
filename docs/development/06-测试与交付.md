# 06 测试与交付

## 1. 开发完成后的最小动作

至少做这些事：

```bash
npm run lint
npm run test:unit
```

如果改到数据库、Admin、路由或 provider，再跑：

```bash
npm run test:integration
```

## 2. 当前建议的最小验证集

### 静态检查

```bash
node --check src/services/telegram.js
node --check src/services/memory-service.js
node --check src/models/sync-job.js
node --check src/admin/server.js
```

### 单测

优先看：

- `tests/unit/models/knowledge.test.js`
- `tests/unit/services/memory-service.test.js`

### 手工验证

1. `npm start`
2. `npm run admin`
3. 发一轮 Telegram 消息
4. 看 Dashboard 和 `/admin/sync-jobs`

## 3. 当前重点测试面

### 短期上下文

- `Message.getRecentMessages()` 边界
- prompt 组装时 recent messages 顺序与截断

### 长期记忆

- `Profile` 读写
- memory merge / dedupe
- “回复后异步更新 profile”的链路

### Knowledge RAG

- provider contract
- Haystack 超时 / 降级
- `global + user-scoped` 过滤

### Admin

- `/admin/profiles`
- `/admin/knowledge`
- `/admin/sync-jobs`

## 4. 当前已知现实

- 当前仓库仍以最小验证为主，不是完整测试覆盖
- v2 新增的工程层需要逐步补更多单测和集成测试
- 如果本地 DB 或 Haystack 没启动，很多验证只能做到静态层和局部单测

## 5. 交付前检查清单

1. 对应文档已同步更新
2. 没有把职责写到错误层
3. 没有留下临时脚本或临时文档
4. 至少跑过一轮静态检查或最小单测
5. 能准确说明“已经实现”和“仍在规划”的边界
