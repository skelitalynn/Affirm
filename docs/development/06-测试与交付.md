# 06 测试与交付

**更新日期**：2026-04-16
**当前状态**：已补齐 retrieval / rerank / prompt trace / embedding fallback / governance 的自动化回归保护；交付时建议按分项命令验证，不依赖单个聚合命令。

## 1. 开发完成后的最小动作

至少做这些事：

```bash
npm run lint
npm run test:unit
```

如果改到数据库、Admin、路由或 provider，再跑：

```bash
npm run db:migrate
npm run test:integration
npm run test:misc
```

如果改到 `memory_events` 召回、排序、fixture 或 eval 工具，再补：

```bash
node tools/evaluate-memory-recall.js --fixture=baseline
```

node --check src/services/telegram.js

### 单测

当前 `test:unit` 应只覆盖不依赖真实数据库的测试。

优先看：

- `tests/unit/services/memory-retrieval-service.test.js`
- `tests/unit/services/memory-embedding-service.test.js`
- `tests/unit/services/conversation-trace.test.js`
- `tests/unit/services/memory-service.test.js`

依赖真实数据库的模型测试应放到 integration 层，而不是 unit 层。

### 手工验证

1. `npm start`
2. `npm run admin`
3. 发一轮 Telegram 消息
4. 看 Dashboard 和 `/admin/sync-jobs`

## 3. 当前重点测试面

### 短期上下文

- `Message.getRecentMessages()` 边界
- prompt 组装时 recent messages 顺序与截断

### 长期记忆

- `Profile` 读写
- `memory_event_candidates` 写入
- “回复后异步更新 profile”的链路

### 历史召回与排序

- `MemoryRetrievalService.searchRelevantEvents()`
- hybrid retrieval + rule-based rerank
- 召回计数更新失败时的降级
- `memory_ranking_version` 与 `memory_refs` trace

### Embedding 降级

- 远程 embeddings 不可用时退回 deterministic 模式
- provider 鉴权或网络异常时不拖垮 retrieval

### Knowledge RAG

- provider contract
- Haystack 超时 / 降级
- `global + user-scoped` 过滤

### Admin

- `/admin/profiles`
- `/admin/memory-events`
- `/admin/knowledge`
- `/admin/sync-jobs`
