# 数据库设计

**更新日期**：2026-04-04

## 1. 数据库文件来源

当前数据库结构有两个来源：

1. 初始 schema：
   `scripts/database/schemas/init.sql`
2. 增量迁移：
   `scripts/database/migrate.js`
   和 `migrations/*.sql`

开发时不要只改其中一个。

## 2. 当前表

### `users`

用户主表，按 `telegram_id` 建唯一约束。

### `profiles`

用户画像表，存：

- `goals`
- `status`
- `preferences`

### `messages`

对话消息表，存：

- `role`
- `content`
- `metadata`
- `embedding`

注意：

- `embedding` 列仍存在
- 但当前 `messages` 文本语义检索已停用
- 不要把它误当作当前主 RAG 入口

### `knowledge_chunks`

当前真正用于 RAG 的表，存：

- `content`
- `source`
- `user_id`
- `embedding`
- `metadata`

`metadata` 当前至少承载：

- `source`
- `user_id`
- `scope`

导入时还可能带：

- `created_by`
- `import_batch`
- `chunk_index`
- `chunk_count`

### `sync_jobs`

记录同步任务状态，主要用于归档类流程。

### `schema_migrations`

记录已执行的 SQL 迁移文件。

## 3. 当前 knowledge 迁移

当前仓库里的增量迁移：

- `migrations/20260404_add_knowledge_chunks_metadata.sql`
- `migrations/20260404_sync_knowledge_chunks_metadata_columns.sql`

作用：

1. 为 `knowledge_chunks` 增加 `metadata`
2. 用触发器在 `metadata` 与旧列 `source/user_id` 之间保持同步

## 4. 索引

关键索引来自 `scripts/database/schemas/init.sql`：

- `idx_messages_user_created`
- `idx_messages_embedding`
- `idx_knowledge_embedding`
- `idx_sync_jobs_date`

其中最关键的是：

- `idx_knowledge_embedding`：knowledge RAG 检索
- `idx_messages_user_created`：最近消息上下文

## 5. 改数据库时的固定流程

1. 先改 `scripts/database/schemas/init.sql`
2. 再新增一个 `migrations/*.sql`
3. 执行：

```bash
npm run db:migrate
```

4. 如果会影响查询或写入，再补测试
5. 最后更新本文件和对应流程文档

## 6. 开发时最常用的核对点

- 表有没有在 `init.sql` 和迁移里同时体现
- 新列是否需要索引
- 新列是否影响 Admin 列表、写入或 RAG 过滤
- `knowledge_chunks.metadata` 是否仍与 `source/user_id` 同步
